===============================================================================
 SorkWhare Compare (R) - HeckSoft, a King of Heck Company (TM)
 (originally "DocCompare" through v0.2.4)
 CHANGELOG
 A single-file, offline, browser-based Word (.docx) redline / compare tool.
 No install, no internet, no upload - files never leave the machine.
===============================================================================

Newest version first. Dates in 2026. Version numbers are preserved as they were
assigned during development (numbering is not sequential/uniform by design).


-------------------------------------------------------------------------------
 v1.5.0  -  Configurable Rendering Sets              (2026-08-15)
-------------------------------------------------------------------------------
 - Added a "Rendering set" picker to choose how changes are styled.
 - Three sets ship - SorkWhare (the original look), Litera Classic, and High
   contrast - and the choice is remembered between sessions.
 - Litera Classic matches the familiar legal-redline convention: pure blue
   double-underlined insertions and pure red struck-through deletions, with no
   background shading.
 - High contrast uses colour-vision-safe colours and gives every change type
   its own underline style, so the types stay tellable apart without relying
   on colour alone.
 - The chosen set applies to the on-screen redline and to the exported PDF.
 - The change bars in the margin stay a single near-black in every set.

-------------------------------------------------------------------------------
 v1.4.1  -  Dense-Rewrite Grouping                   (2026-08-15)
-------------------------------------------------------------------------------
 - When a whole phrase is reworded but keeps a short joining word (like "of" or
   "and") in the middle, the change is now shown as one struck-through phrase
   followed by one inserted phrase, instead of being chopped into two smaller
   edits around the shared word - the cleaner presentation redline tools use.
 - Longer unchanged runs (two or more words) are still kept in place, so nothing
   that actually stayed the same gets pulled into the change.

-------------------------------------------------------------------------------
 v1.4.0  -  Vertical Change Bars                     (2026-08-15)
-------------------------------------------------------------------------------
 - A vertical change bar now appears in the left margin beside every changed
   line, both on screen and in the downloaded PDF - the same margin revision
   bar that professional redline tools use, so changes are easy to scan.
 - One neutral colour marks every change type; the kind of change is still
   shown by the existing labels and the coloured inserted / struck-through text.
 - Formatting-only changes get a bar too; it follows the "Formatting" filter,
   disappearing when formatting changes are hidden.

-------------------------------------------------------------------------------
 v1.3.2  -  Formatting Change Detection              (2026-08-14)
-------------------------------------------------------------------------------
 - Formatting-only changes are now caught: when the text is unchanged but its
   bold, italic, underline, font, or size changed, the affected words are
   marked with a dotted underline and a hover note saying what changed.
 - Formatting changes are shown but NOT counted as numbered changes, so the
   change total keeps meaning substantive text edits.
 - A new "Formatting" show/hide filter toggles them on screen and in the
   downloaded PDF - hide it for a clean PDF with only the text changes.
 - In the PDF, each formatting change is underlined and annotated inline
   (e.g. "[formatting: bold added]"), since there is no hover there.

-------------------------------------------------------------------------------
 v1.3.1  -  Hardening Release                        (2026-08-14)
-------------------------------------------------------------------------------
 - Tables that don't declare a fixed column layout no longer split into
   several separate tables when their rows have different numbers of cells.
 - A page break inside a table cell no longer spills onto the paragraph after
   the table; a page break just before a table still starts it on a new page.
 - Rewritten passages that contain a bold word are no longer over-collapsed in
   the inline redline - they stay one deleted phrase then one inserted phrase.
 - "At least" line spacing now grows with content on screen, matching the
   exported PDF and Word instead of being pinned to a fixed height.
 - Page-fit estimates now count the spacing after a paragraph kept with the
   next one, and split a page-tall table between its rows.
 - Paragraph spacing shown on screen now matches the exported PDF when Show
   filters hide some paragraphs.
 - Error messages are escaped, so a document's file name can never inject
   markup into the app.

-------------------------------------------------------------------------------
 v1.3.0  -  Redline Quality Release                  (2026-08-14)
-------------------------------------------------------------------------------
 - Tables are real tables now: cells, rows, and whole added/deleted table rows
   render as bordered grids on screen, in print, and in the downloaded PDF
   (pages break between table rows, never through one).
 - Rewritten passages read like Workshare: dense word-by-word alternations
   collapse into one struck-out phrase followed by one inserted phrase.
 - Money, dates, and quantities replace whole: $486,000 -> $528,000 is one
   clean change, never a mid-number split.
 - Unchanged table cells stay visible under the "unchanged" filter so tables
   keep their context; adjacent tables no longer merge into one grid.
 - Benchmarked against an external Workshare comparison test pair:
   all 40 substantive changes detected and cleanly presented.
 - Known limits: nested tables render as flattened cell text; page ranges
   like 3-5 now replace as one token.

-------------------------------------------------------------------------------
 v1.2.0  -  PDF Fidelity Release                     (2026-08-13)
-------------------------------------------------------------------------------
 - Native PDF now renders in the document's real font (when installed), with
   correct measurements - not everything-is-Times anymore.
 - Real paragraph and line spacing (w:spacing, contextual spacing) drive
   layout on screen, in print, and in the downloaded PDF.
 - Disciplined page breaks: headings keep with their body text; no more
   widowed/orphaned single lines at page boundaries.
 - Print path and on-screen page estimates inherit the same spacing data, so
   all three views agree.


-------------------------------------------------------------------------------
 v1.1.5  -  Robustness release                       (2026-08-13)
-------------------------------------------------------------------------------
 - Project is now a git repository (baseline tagged v1.1.4); proper semver from
   here on: patch = fixes, minor = features, major = breaking.
 - Finished the HeckSoft rename that v1.1.4's changelog claimed (browser title
   and header tagline still said "HeckNet").
 - Removed the "Ignore whitespace" checkbox: it was never wired up, and the
   extractor always normalizes whitespace before the diff (correct for legal
   comparison), so the option was structurally a no-op.
 - "Total" now counts unique numbered changes and always agrees with the
   "Change X of Y" navigation; new "Amendments" chip shows composition
   (Insertions/Deletions tiles keep their old per-side meanings).
 - Ctrl+P and j/k no longer misfire on the setup screen (state flag instead of
   inline-style sniffing).
 - Sidebar snippets are truncated tag-safely (no more broken HTML bleeding
   colours into the change list).
 - XML entity decoding fixed (&amp; decoded last; numeric &#NNN;/&#xHHH;
   references now supported).
 - Diff engine rebuilt for bounded memory: common prefix/suffix trimming,
   patience-style recursion on unique paragraphs, exact DP on small middles.
   Identical output for normal documents; 10,000-paragraph compares no longer
   risk a tab crash. Inline diffs cap at 4,000 tokens/side (whole-paragraph
   replace beyond that).
 - Paragraph pairing and move detection use a cheap bag-of-words upper bound
   before running full LCS similarity — same pairings, much faster on heavily
   rewritten documents.
 - Warns when a source document contains unaccepted tracked changes (compared
   as if all changes were accepted — which is what the engine always did).
 - Nav status shows the estimated page count ("~N pages").
 - Honest error messages: "not a ZIP archive" vs "appears to be corrupt" vs
   "document.xml not found".
 - Print button now respects the Show filters, matching the native PDF.
 - Final-review fixes: the page estimate skips filter-hidden paragraphs (their
   margins had inflated the count); the native PDF's redline parser now also
   decodes &amp; last (same double-decode class as the unxml fix); capped
   inline diffs no longer emit an empty <del>/<ins> for a one-sided change.
 - Validation: Node test suite (30 checks, run with bare "node --test") +
   in-browser smoke test (counts, navigation, guards, tracked-changes banner).

 v1.1.3  -  Faithful paragraph formatting            (2026-07-29)
-------------------------------------------------------------------------------
 - Fixed lost paragraph JUSTIFICATION and too-narrow indents.
 - Now parses Word alignment (w:jc) and indentation (w:ind: left / hanging /
   first-line) from the paragraph, the numbering level, and the style
   (with basedOn inheritance).
 - Body text renders justified; title centered; numbered clauses use the
   document's real indents:  "1." at 0.5in,  "(a)" at 1.0in,  "(i)" at 1.5in,
   each with a proper hanging indent for the marker.
 - Applied in BOTH the on-screen view and the native PDF (justify distributes
   space on all lines except the last; center/right supported).
 - Added a Times-Roman font-metrics table so text measures accurately even
   when the browser Canvas API is unavailable.
 - Root cause noted: the page margins were always correct; the "narrow
   margins" look was really the too-shallow flat indent.
 - Validation: 8/8 headless checks.

 v1.0.5  -  Native vector-PDF export                 (2026-07-29)
-------------------------------------------------------------------------------
 - The "PDF" button now builds a REAL PDF file in pure JavaScript and
   downloads it directly - no browser print dialog, so NO auto-injected
   date / URL / page-number headers and footers.
 - Pure JS, fully offline, no libraries: writes valid PDF 1.4 (catalog,
   pages, per-page content streams, xref, trailer) using the base-14 Times
   family (no font embedding). Output text is selectable / searchable.
 - Honours page geometry (v1.0.4) and explicit page breaks (v1.0.3);
   reproduces the redline palette (insert = blue underline, delete = red
   strikethrough, move = green). WinAnsi encoding for smart quotes, dashes,
   bullets, accents. Saves as "<revised> - Redline.pdf".
 - Removed the word "estimated" from the on-screen page-break divider label.
 - Fixed the browser Print button (it had rendered into a 0x0 iframe that
   some Chromium builds refuse to print); it is now a secondary "Print"
   option (the path that can add browser headers/footers).
 - Validation: generator self-checks 14/14; verified with poppler (pdfinfo:
   9 pages, Letter) and pypdf (selectable text).


-------------------------------------------------------------------------------
 v1.0.4  -  Reproduce Word's automatic pagination    (2026-07-29)
-------------------------------------------------------------------------------
 - Fixed a document that is 9 pages in Word showing only one page break.
 - Diagnosis: the .docx stored only ONE explicit break; the other ~8 page
   transitions are Word's automatic content-flow pagination and are not
   stored in the file at all.
 - Added parsing of real page geometry from the section properties (page
   size and margins, twips -> inches) and the document's default font size
   and family.
 - The on-screen "paper" and the print/PDF @page are now driven by that real
   geometry, so the browser's automatic pagination lands close to Word's; an
   estimated page-break divider is shown on screen where content overflows.
 - Honest limitation: this is an approximation - browser line-breaking differs
   slightly from Word's, so estimated breaks can drift a line or two over many
   pages. Explicit breaks remain exact.
 - Validation: geometry parse 7/7; explicit-break regression 5/5.


-------------------------------------------------------------------------------
 v1.0.3  -  Honour Word page breaks in print/PDF     (2026-07-29)
-------------------------------------------------------------------------------
 - The redline now paginates like the source Word document for the breaks the
   file actually stores. Detects three signals per paragraph:
     1. "Page break before" paragraph formatting (respects the off value).
     2. Manual page break (Ctrl+Enter):
          - before the paragraph's text -> break belongs to this paragraph;
          - after the text              -> break belongs to the next one.
        A break sitting in an otherwise empty paragraph is carried forward
        (previously it was dropped with the empty paragraph).
     3. In-paragraph section break: Next Page / Odd / Even (or none) breaks
        after the paragraph; Continuous / New Column do not.
 - On screen, a "Page break" divider is shown; a real page break is emitted
   for print/PDF; suppressed on the very first paragraph so the document
   never opens with a blank leading page.
 - Validation: 9/9 synthetic break cases.

 - First branded release: renamed "DocCompare" -> "SorkWhare Compare". Company line "HeckNet".

-------------------------------------------------------------------------------
 v0.2.4  -  Clean PDF export via hidden iframe
-------------------------------------------------------------------------------
 - Replaced the plain window.print() with an exportPdf() routine that renders
   into a hidden iframe, clones the page's styles, and preserves the current
   on-screen filter (e.g. show/hide unchanged) in the printed output.
 - Avoids scroll-container clipping and popup blockers; Ctrl/Cmd+P now routes
   through the same clean export when results are showing.
 - (This is the direct ancestor of the later "Print" path; the native
   vector-PDF generator did not arrive until v1.0.5.)

-------------------------------------------------------------------------------
 v0.2.3  -  Faithful bold (fix "everything bold")
-------------------------------------------------------------------------------
 - Rewrote paragraph extraction to be run-aware: each <w:r> run's bold state
   is read and a bold-character ratio is accumulated (isBold >= 60%).
 - Bold is now driven by ACTUAL run formatting rather than outline level, so
   true section headings (e.g. "Background") render bold while numbered body
   clauses that merely contain a few bold defined terms stay normal weight.
 - Added the .para.bold styling and the 'bold' class in paragraph rendering.

-------------------------------------------------------------------------------
 v0.2.2  -  Correct headings & multilevel numbering
-------------------------------------------------------------------------------
 - Heading detection restricted to an explicit "Heading N" / "Title" style;
   stopped inferring headings from outlineLvl (which had been enlarging/
   bolding legal sub-paragraphs like "(e)").
 - Numbering counter reworked to a single cascading counter keyed by LEVEL
   (not by list id): incrementing a shallower level (a new section "2.")
   resets deeper levels so "(a)" restarts under each section - even when the
   section headings and sub-clauses live on different list definitions.
 - A heading also resets any deeper numbered sub-lists beneath it.

-------------------------------------------------------------------------------
 v0.2.1  -  Defaults & heading style polish
-------------------------------------------------------------------------------
 - "Unchanged text" now shown by default (filter checked on load).
 - Minor heading typography tweaks (h4-h6 rendered at 600 weight, italic).

 v0.2.0  -  Workshare-style redline baseline

   with Total / Insertions / Deletions / Moves counts, category chips, a

   keyboard shortcuts (arrows / j / k).
 - Move detection with an adjustable move-threshold (words) option.
 - Styles/numbering parsing incl. style-to-number mapping (styleToNum).

-------------------------------------------------------------------------------
 v0.1.2  -  Focused redline rewrite
-------------------------------------------------------------------------------

-------------------------------------------------------------------------------
 v0.1.1  -  "Workshare-style" rewrite (major)
-------------------------------------------------------------------------------
 - Reworked into a full-height app with a setup screen and a results screen.
 - Added a Change Summary sidebar: total, insertions/deletions/moves, and a
   by-category breakdown (Content / Numbering / Punctuation / Tables).
 - MOVE DETECTION (moved-out / moved-in) with a move tag in the document.

-------------------------------------------------------------------------------
 v0.1.0  -  First working build  ("DocCompare - Word Document Blackline")
-------------------------------------------------------------------------------
 - The original proof of concept. Runs entirely in the browser; no install,
   no internet, no upload.
 - Pure-JS .docx (ZIP) reader using DecompressionStream; parses document.xml,
   styles.xml and numbering.xml with no external libraries.
 - Structured extraction preserving headings, list numbering and bullets
   (decimal / letter / roman / bullet formats, multi-level indent).
 - Paragraph-level LCS blackline with word-level inline insert/delete, and
   similarity-based pairing of changed paragraphs.
 - Stats bar (Amended / Inserted / Deleted / Unchanged) and a printable
   blackline document view.
 - "Flag key legal terms" scanner (liability, indemnity, termination,
   assignment/change of control, confidentiality, governing law, warranty,
   IP, insurance, term, payment/price).
 - Options: ignore case, ignore whitespace, show unchanged text, flag key
   legal terms. PDF via browser print.


===============================================================================
 KNOWN LIMITATIONS (current)
===============================================================================
 - Pagination approximates Word's layout engine; over many pages a break can
   drift by a line or two. Explicit page breaks are exact.
 - The native PDF reproduces the redline content and formatting (justification,
   Word indents, inline bold) but not every Word visual: tables render as
   text; no headers/footers/footnotes/images; italic and underline from the
   source are not yet tracked (only bold).
